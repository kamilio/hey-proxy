Request detail

Observe the traffic you actually serve.

This dashboard adapts the compact overview, metric browser, and chart drilldowns of Xiaomi MiMo’s live RL dashboard to hey-proxy. Its charts describe inference traffic recorded by this proxy.

Reading the charts

Each line represents a model, grouped by the requested or destination name you select. Charts use 30 equal time buckets; values belong to the request’s start time. Metric headers summarize the entire selected window. Smoothing applies an exponential moving average to lines only; hovering always shows raw measurements. Gaps mean no measurement is available.

Requests & rates
Requests observed in the selected window, including requests without a model. Request rate divides each bucket’s count by its duration in minutes.
Tokens
Upstream-reported input and output tokens. Missing usage is unavailable, never estimated. Totals can be partial; usage coverage counts requests with at least one reported token field. Cached input and reasoning are included when upstream includes them.
Success & errors
Known HTTP / WebSocket send statuses below 400 are successful; 400 and above are errors. Pending statuses are excluded from the denominator. A successful status does not prove that a streamed response completed successfully.
Response timing
HTTP: time until response headers are returned, including retries. WebSocket: time to the first send of a model-bearing message upstream, excluding later recovery. Neither is end-to-end generation time or time to first output token. Percentiles use the nearest-rank method.
Retries
Additional upstream attempts reported on the original request, including internal recovery. A retried request can succeed.

Estimated spend at regular model list prices

Rates are in USD per million tokens from OpenAI’s published standard pricing, checked . When the destination is a regular model, its price applies. Otherwise, the requested regular model name supplies the price: gpt-4.1 → custom-model uses the requested model’s list price. Unknown models stay unpriced.

Spend requires both input and output usage. Ordinary input, cache reads, and cache writes use their respective rates. Unreported cache details are treated as ordinary input. For supported models above 272,000 input tokens, the full request uses 2× input/cache rates and 1.5× output rates. Pricing coverage is shown beside the total. Standard rates are used regardless of the request’s service tier.

This estimates the list-price value of retained text-generation usage, not your upstream invoice. It excludes unreported usage, unobserved retry charges, tool fees, image/audio generation, taxes, discounts, and tier premiums. Retrieving an existing response does not add spend. Older remote proxies may lack cache details, which can overstate input cost.

Collection and retention

Local snapshots refresh every five seconds. Configured SSH machines refresh every 10 seconds and must have synchronized clocks. Unreachable machines are marked unavailable. Client relays are excluded by default because their hosts also record the same traffic; including relays may double-count it.

The overview, metrics, and requests tabs read retained SQLite history for the selected window, up to 50,000 records per machine, and merge recent in-memory updates. A coverage note marks capped windows, missing machines, and older proxies that only expose a 500-request memory sample. Reports reads all local SQLite history, retained across restarts. Reports uses completed response lifetimes, separate from live header/send status. A cancelled response, missing Responses completion event, or failed stream is not a completed success. Pausing freezes the live snapshot; historical reports refresh on demand. Metadata is queued to a dedicated writer, so a crash can lose events not yet committed. Logging health exposes pending events, write errors and dropped events.

Privacy and access

Dashboard history contains no prompts, request bodies, query strings, or actual API keys. Key project names identify routing configuration only. Host mode requires the existing host access key. The dashboard uses local assets and the existing /logs/api endpoint.
